Как устроен модуль: 8 уроков, ~30–40 минут, если делать руками. Каждый урок — «сделайте прямо сейчас», а не «посмотрите видео».

Сквозной пример: мы не «устанавливаем программу» — мы настраиваем вашего AI-ассистента так, чтобы он понимал ваш тон, ваши задачи и не отвлекал на лишнее. К концу модуля Claude Code здоровается с вами, у него есть CLAUDE.md с вашим стилем, и вы увидели «план-mode» для контент-планирования.

Предпосылки: браузер, компьютер (Windows или Mac), желание автоматизировать — всё. Установка — первый шаг.

01-1-устанавливаем-claude-code #

Урок 01.1 — Устанавливаем Claude Code #

⏱ ~5 минут · 🎯 Цель: Claude Code стоит на вашем компьютере и понимает, что вы — не разработчик, а человек, который пишет, планирует и публикует контент.

!СКРИНШТОТ: первый запуск Claude Code — окно приветствия

Что мы ставим и зачем #

Claude Code — это программа, внутри которой живёт Claude (AI-ассистент), но с «руками»: он умеет создавать файлы на вашем компьютере, писать черновики, анализировать конкуренцию, планировать публикации. Обычный чат в браузере умеет только советовать. Claude Code умеет делать — и оставляет результаты в ваших файлах, а не в истории переписки.

Путь А — десктоп-приложение (рекомендую) #

  1. Откройте <code>claude.com/download</code> в браузере.
  2. Скачайте версию для вашей системы — как любое привычное приложение.
  3. Установите: дважды кликнули, согласились. На рабочем столе появилась иконка Claude.

Путь Б — терминал (если хотите «как у профессионалов») #

Терминал — чёрное окно, где компьютеру пишут команды текстом. На Windows — PowerShell, на Mac — Терминал.

  1. На официальной странице установки Claude Code всегда лежит одна готовая строчка-команда.
  2. Скопируйте её, вставьте в терминал, нажмите Enter. Всё установится само.
$ <строка установки, скопированная с claude.com/download>
Установка... Готово.

$ claude
Добро пожаловать! Я умею создавать файлы, писать и запускать код.
Что будем делать?

🚨 Важно: копируйте команды установки только с официальной страницы. «Советы» из случайных блогов — это как брать таблетки по совету из лифта.

Первый запуск и вход #

  1. Откройте приложение (или введите <code>claude</code> в терминале и нажмите Enter).
  2. Программа предложит войти. Вариантов два:
    • Войти в аккаунт Claude (тот же, что для чата) — расходы покрывает ваша подписка Pro/Max. Самый простой путь.
    • Использовать API-ключ — отдельный «кошелёк» с оплатой по факту использования. Ключ создаётся в личном кабинете разработчиков Anthropic: кнопка «Create API key», скопировали длинный код, вставили.

Попробуйте сейчас: откройте Claude Code, напишите «Привет! Я контент-менеджер, давай приветствие на русском» — Claude ответит. Если ответило — всё работает.

01-2-зоны-claude-code-cowork-manage #

Урок 01.2 — Зоны Claude: code, cowork, manage #

⏱ ~3 минуты · 🎯 Цель: вы понимаете, в каком режиме Claude вам отвечает — и не тратите время на попытки заставить его писать код, когда нужен контент.

Три зоны работы Claude #

ЗонаКогда использоватьПример для КМ
Code — Claude пишет и запускает кодКогда нужен файл, сайт, скрипт, автоматизация«собери HTML-лендинг из брифа», «напиши скрипт для сбора заголовков из CSV»
Cowork (совместная работа) — Claude работает с вашими файлами, но не запускает код самКогда нужно обсудить, проанализировать, переписать, собрать план«проанализируй 5 конкурентов из CSV», «перепиши заголовки в моём стиле», «составь план контента на неделю»
Manage — Claude управляет процессами, библиотеками, операторомКогда настроили оператора Hermes (М05) и рутины — Claude сам напоминает, собирает, отчитывается«оператор, собери сегодняшнюю аналитику», «передай кейс в витрину»

Для контент-менеджера основная зона — Cowork. Вы обсуждаете тексты, проектируете планы, анализируете — и Claude работает с вашими файлами. Code нужен, когда строите сайт-витрину (М02). Manage — когда настроили оператора (М05).

Попробуйте сейчас: спросите Claude в Cowork: «проанализируй, чего не хватает в идее лендинга контент-менеджера» — Claude предложит идеи, но не пытается это реализовать кодом. Это Cowork.

Проект: контент-менеджмент [ваше имя / бренд] #

Урок 01.3 — CLAUDE.md: ваш стиль-гайд как проектный документ #

⏱ ~8 минут · 🎯 Цель: вы создали CLAUDE.md для вашего проекта «контент-менеджмент» — и Claude отвечает в вашем стиле без подсказок с каждой стороны.

Что такое CLAUDE.md #

CLAUDE.md — это правила проекта, которые Claude читает каждый раз перед ответом. Это не «системный промпт» — это договор «как мы работаем вместе» на вашем проекте. Если Claude.md написан хорошо, вы больше не объясняете «пиши читаемо, без канцелярита» с каждой стороны — Claude уже это знает.

Для контент-менеджера CLAUDE.md — это стиль-гайд + регламент работы. В нём прописано:

  • Как пишете вы (тональность, структура, запрещённые слова)
  • Что храните в папке проекта (черновики, планы, глоссарий, кейсы)
  • Как работаете с конкурентами (где брать данные, как обезличивать)
  • Что отдаёте клиенту (форматы, сроки)

Анатомия CLAUDE.md для контент-менеджера #

Создайте файл <code>CLAUDE.md</code> в корне вашего проекта (папка <code>контент-менеджер/</code>):


## Тон и стиль

- **Для соцсетей:** коро Channels, эмодзи допустимы, конкретика вместо общих слов. «3 поста в неделю» — не «регулярно».
- **Для лендинга:** спокойный, уверенный, без «мы команда профессионалов». Фокус на результате для клиента.
- **Для кейсов:** три строки: проблема → решение → цифра/результат. Без воды.

## Стоп-слова (не использовать в собственных текстах)

- «индивидуальный подход», «эксперт», «лидер рынка», «уникальный», «нативный»
- «данный», «является», «вскомплекте», «воспользуйтесь»

## Запрещённые приёмы

- Кликабельные обещания без цифры («результат гарантирован» — только с цифрой)
- Никогда не сравниваем клиентов с конкурентами отрицательно — только «у нас X»

## Структура папки проекта

контент-менеджер/ ├── CLAUDE.md ← этот файл ├── BRIEF.md ← бриф: ниша, посетитель, задача сайта, тон ├── стиль-гайд.md ← шпаргалка по стилю (расширенная) ├── планы/ ← контент-планы (네스젝, посты, рассылки) ├── кейсы/ ← готовые кейсы (только обезличенные!) ├── глоссарий.md ← термины, которые важно понимать одинаково ├── конкуренты/ ← данные по конкурентам (обезличенные) └── витрина/ ← файлы лендинга (М02)


## Правила работы с AI

1. **Не отдавать Claude персональные данные клиентов** — только обезличенные кейсы (ФИО → «клиент из Омска, сфера — стоматология»).
2. **Цитаты — только с указанием источника.** Если Claude утверждает цифру — он обязан показать, откуда (урок 03.4 про critic loop).
3. **Перед отправкой клиенту** — всегда прогнать через «стиль-гайд» (урок 03.2 про review).

**Попробуйте сейчас:** создайте папку `контент-менеджер/` и файл `CLAUDE.md` по шаблону выше. Скопируйте, замените на свой стиль. Потом спросите Claude «проанализируй этот заголовок на соответствие стилю» — он прочитает CLAUDE.md.

Урок 01.4 — Plan Mode: план контента как требование #

⏱ ~5 минут · 🎯 Цель: вы увидели Plan Mode — и поняли, зачем он нужен для контент-планов.

Что такое Plan Mode #

Plan Mode — это режим Claude, когда он сначала пишет план, а потом исполняет. Не «сделай сразу», а «давай сначала составим план, согласуем, потом сделаем». Для контент-менеджера это критично: вы не хотите, чтобы Claude «включался и писал», вы хотите, чтобы план был — и вы его утвердили.

Как включить #

В Claude Code там, где вы пишете запрос, есть переключатель режима. Или команда <code>/plan</code>.

Пример диалога:

Диалог:
КМ: Составь план контента для Instagram на следующую неделю.
   Тема: как бизнесу держать клиентов после покупки.
   Стиль: по моему CLAUDE.md.
   Сегодня четверг, публикации — понедельник и среда.

Claude (Plan Mode): [пишет план, ждёт одобрения]
КМ: хорошо, делай.
Claude: [исполняет план — пишет черновики в папку планов/]

Зачем для контент-менеджера Plan Mode #

  1. Планирование ≠ исполнение. Вы хотите видеть весь недельный план одним взглядом — это даёт Plan Mode.
  2. Цифры и факты — в плане Claude обязан указать, откуда он знает цифру. Критично для кейсов.
  3. Согласование. Вы изменили какой-то день — Claude пересобрал план, не переписывая всё с нуля.

Попробуйте сейчас: вызовите Plan Mode и скажите «составь план постов Instagram на 3 дня, тема — «что делать, когда клиент не платит»». План получите без одного слова исполнения.

Урок 01.5 — Токены и целесообразность: дешево ≠ автоматически #

⏱ ~4 минуты · 🎯 Цель: вы понимаете, когда AI-инструмент выгоден, а когда — трата токенов, и научились выбирать.

Что такое токены (просто) #

Токены — это «единицы работы» Claude. Чем длиннее запрос и ответ — тем больше токенов, тем больше стоимость (если платите по API) или тем больше времени (если платите подписку). Для КМ-а это мастер-класс: не каждая задача требует AI.

Когда AI-ассистент выгоден #

ЗадачаИспользовать AI?Почему
Черновик поста в соцсетьДаЗа 30 секунд — черновик, который вы правите 5 минут, а не пишете с нуля за час
Анализ 10 конкурентовДаЧеловек прочитал бы 2 часа; AI покажет структуру за минуту

Когда AI-ассистент — перерасход #

  • Краткий ответ давно известный вам («какие цвета в бренд–буке» — если он у вас в папке, открывайте папку, не спрашивайте AI).

Попробуйте сейчас: возьмите задачу, которая у вас стоит «на месяц» (составить календарь публикаций, проанализировать конкурентов, переписать шаблон email-рассылки), и спросите себя: «это выполнимо за 15 минут с AI, или без него — час?». Если 15 минут — отличная задача для курса.

01-6-дебриндинг-источников-откуда-claude-знает #

Урок 01.6 — Дебриндинг источников: откуда Claude знает? #

⏱ ~4 минуты · 🎯 Цель: вы умеете проверять, насколько Claude прав, и запрашивать источник. Никаких «вот выдуманные кейсы» в вашем портфолио.

Проблема — Claude иногда «уверенно неправ» #

Claude — не эксперт по вашей нише. Он говорит текст, который звучит уверенно, но цифры и утверждения могут быть обобщёнными. Проблема для КМ — если вы вставите в кейс сумму «£7.5k» из ответа Claude, а это выдумка — ваш портфолио подрывает доверие.

Правило курса: цифры с источником #

Каждое утверждение Claude, которое вы планируете отдать клиенту или вставить в кейс, должно иметь источник.

Как запрашивать:

«Сколько стоит контент-менеджмент в России в 2025?»
→ Claude: «в диапазоне 50–150 тыс. руб. в месяц, источник — вакансии HH и отзывы»
   → плохо: без источника
   → хорошо: скопировали ссылку на источник

«Приведи пример кейса»
→ Claude: «вот пример» (мог бы выдумать)
   → вы: «источник реального кейса?»
   → Claude: «в моём обучающем наборе нет реального кейса — возьмите заглушку, но пометьте «ЗАМЕНИТЕ»»

Заглушки помечаются <code>ЗАМЕНИТЕ</code> — файл с готовым образцом, но без реальных данных. Пока не заменили — в портфолио не вставлять.

Дебриндинг конкурентов (крепкая сторона для КМ) #

Claude отлично анализирует тексты и структуры, которые вы ему даёте. Конкурентный анализ — это не «спроси Claude, кто лидеры» — это «дай Claude 5 ссылок или скриншотов и скажи, что общего в структуре».

Попробуйте сейчас: откройте 3 лендинга конкурентов-контент-менеджеров. Скопируйте URL или скриншоты. Спросите Claude: «на эти три страницы — какие блоки общие? Чем отличается информация о себе?». Результат — структура из 5–7 общих блоков.

01-7-git-и-права-файлы-вашего-контента-в-безопасности #

Урок 01.7 — Git и права: файлы вашего контента в безопасности #

⏱ ~4 минуты · 🎯 Цель: вы поняли, зачем Git нужен для контента, и как настроить права Claude, чтобы он не удалил не тот файл.

Зачем Git контент-менеджеру #

Git — это «система версий». Если вы отредактировали черновик и потом поняли, что «а в старой версии было лучше» — Git это откатит. Для КМ это проще, чем «сохранил как черновик_2_финал_вроде_так».

Кроме того, все файлы проекта в Git — это ваша резервная копия на случай формата. И когда вы сдаёте работу клиенту — вы «отдаёте коммит», а не «отправляете файлик».

Базовая установка Git #

  1. Установите Git (git-scm.com) — как любое приложение.
  2. В папке проекта выполните:
$ git init
$ git add .
$ git commit -m "Начало проекта контент-менеджера"
  1. Добавьте .gitignore на случай, если в папке будут временные файлы Claude.

Права Claude: «спрашивай, прежде чем удалять» #

В CLAUDE.md (который мы сделали в уроке 1.3) есть правило: Claude не удаляет файлы без запрашивания. Это одна строка в настройках Claude Code:

В CLAUDE.md проекта добавить:
- «БEFORE удаления или переименования любого файла — спросить подтверждение».

Это значит, что Claude будет спрашивать: «Удалить файл <code>старый-план.md</code>?» — и вы будете видеть, что происходит.

Попробуйте сейчас: создайте тестовый файл в папке проекта, попросите Claude «создай дубликат этого файла в папке backup/», затем «удали дубликат» — Claude спросит. Это правило работает.

Урок 02.1 — Система трёх шагов: почему начинаем не с «красиво» #

⏱ ~4 минуты · 🎯 Цель: у вас в голове карта маршрута — и вы понимаете, почему начинаем с разведки, а не с «сделай красивый сайт».

Начинать сайт со слов «ну, можно красивое» — это как строить дом, не зная, кто в нем будет жить. Получается дом-среднее-по-больнице. Курс обходит ловушку тремя шагами:

  1. Competitor Intel — разведка. Смотрим 3–5 чужих лендингов в вашей нише и вытаскиваем данные, не «вдохновение»: какие блоки стоят, какие обещания дают, куда ведут кнопки. Чужие деньги уже потратили, чтобы выяснить, что работает — мы читаем их работу.
  2. Design — проектирование и бриф. Данные превращаем в BRIEF.md (техническое задание), и только потом Claude строит. Не «красиво вообще», а «красиво под задачу».
  3. Host — публикация. Сайт переезжает с вашего компьютера в интернет на Vercel. Пока сайт не открылся с чужого телефона — сайта нет, есть файл на локальной машине.

Бриф — это договор «что строим» до стройки #

Спек (спецификация, бриф) — это договор «что строим» до стройки. Без брифа вы платите за переделки: каждая правка «ой, не то» — это время и токены. С брифом Claude с первого выстрела попадает в 80–90% желаемого, а оставшееся докручивается точечными правками.

«Спецификация дешевле переделки» — эпиграф этого модуля.

Что мы реально строим #

Одностраничный лендинг контент-менеджера: первый экран с выгодой и кнопкой, услуги (пакеты), кейсы (пока обезличенные), форма записи на аудит. Технологии нарочно простые: HTML + CSS + капля JS, без «взрослых» фреймворков — чтобы вы видели и понимали каждый файл. Финал модуля: ссылка <code>valentina.vercel.app</code> (ваше доменное имя) открывается с телефона.

Попробуйте сейчас: ответьте письменно на один вопрос — «кто мой посетитель и какое одно действие он должен сделать на сайте?» (Записаться на аудит? Позвонить? Посмотреть кейсы и запомнить имя?) Если действий «пять» — выберите одно главное. Это ядро будущего брифа.

Урок 02.2 — Competitor Intel: разведка 5 лендингов #

⏱ ~15 минут · 🎯 Цель: у вас есть файл <code>конкуренты/анализ.md</code> с выдержками из 5 лендингов — не «мне понравилось», а «они используют X, обещают Y, кнопка ведёт на Z».

Как правильно делать разведку #

Хорошо: вы открыли 5 лендингов конкурентов, прочитали секции, зафиксировали структуру, обещания, кнопки, цены (если видны). Плохо: «мне понравилось» / «красивое» / «отсюда вдохновение».

Разведка — это сбор фактов, а не атмосферы. В итоге вы получите шаблон, который снижает риск: «у всех пятерых на первой позиции — блок с цифрой/результатом», значит, клиент что-то читает в этом формате.

Практический алгоритм #

  1. Найдите 5 ко-конкурентов в вашей нише (контент-менеджеры, копирайтеры, веб-редакторы с витриной). Ищите по запросу «контент-менеджер услуги лендинг», «копирайтер портфолио», «веб-редактор делает».
  2. Откройте каждый в новой вкладке.
  3. Для каждого зафиксируйте:
    • Заголовок/первый экран: что обещают? (цифра? результат? метод? личность?)
    • Основные блоки: что в порядке? (блог/кейсы/услуги/о себе/контакты?)
    • Кнопки и призывы: куда ведут? (запись, рассылка, звонок, скачать?)
    • Цены/тарифы: видны ли? если да — как позиционированы?
    • Личность: «обо мне» — есть ли? как позиционируют? (как эксперт, как сервис, как творческий?)
  4. Скопируйте скриншоты или выделите текст в обезличенном виде.

Что обезличивать обязательно #

  • Имена конкурентов — только если вы готовы, чтобы они увидели. В простом курсе — без имён, «конкурент N».
  • Скриншоты — если на них видны клиенты или партнёры — обрезать или обезличивать.
  • Кейсы конкурентов — не копировать.

Вы не знаете, как выглядит идеально, пока не увидите первый вариант. Итерации — это «посмотрел → увидел, что хочу другое → попросил поменять → посмотрел снова».

Кейсы — это не «я сделал, поверьте». Это «вот проблема X, вот как я решил, вот результат». Для КМ кейсы — главный инструмент доверия. Но на этапе сборки лендинга у вас может не быть реальных кейсов (или не хочется их показывать).

1. Анализ: почему уходят (интервью с 5 «ушедшими» — обезличенные)
2. Стратегия контента: блог + соц-лента + email-цепочка для новых подписчиков
3. Реализация: 3 недели контента + запуск цепочки

## Результат
- Конверсия из посетителя в покупателя: [цифра — пока заглушка, в М07 заменить на реальную]
- Снижение оттока: [цифра]
- Добавлено контента: [число статей/постов]

> Структура кейса: проблема → решение → цифра. Цифра — не выдумка, источник — прайса клиента (обезличенный). В М07 заменить на реальную цифру из работы с клиентом.

Правило обезличивания #

Из курса Модуля 01 (урок 01.6) — каждое утверждение Claude, которое вы планируете отдать клиенту, должно иметь источник. Кейсы — не исключение. Если цифра в кейсе — «результат» — она должна быть реальной из работы с клиентом, а не «что обычно бывает» из головы Claude. Пока нет реальной — кейс с заглушкой, но с каркасом и пометкой ЗАМЕНИТЕ.

Попробуйте сейчас: создайте файл <code>кейсы/ШАБЛОН-кейса.md</code> — по образцу выше, заполните теми данными, которые у вас уже есть (пусть даже «пока не в продакшене»). Это каркас, который Claude будет наполнять в М07.

Vercel — это сервис, который берёт ваши HTML/CSS/JS файлы и делает из них живой сайт в интернете. Кнопка «Deploy» — и через минуту у вас ссылка <code>vash-proekt.vercel.app</code>, которая открывается с телефона.

Обычно статические сайты не требуют поддержки — они просто «лежат» на сервере Vercel. Но есть вещи, на которые стоит обратить внимание:

Урок 03.1 — Skills с нуля: специализации для Claude #

⏱ ~5 минут · 🎯 Цель: вы создали первый Skill — «свой-тон» — и проверили, что Claude его применяет без ваших слов.

Что такое Skill «под капотом» #

CLAUDE.md — правила, включённые всегда. Skill — «специализация по требованию»: толстый набор знаний (дизайн-регламент, тон бренда, шаблон кейса), который Claude подгружает, когда задача совпадает с описанием Skill. Аналогия: CLAUDE.md — распорядок офиса на стене; Skills — папки-регламенты в шкафу: достают, когда пришёл клиент соответствующего типа.

Зачем разделять? Чтобы не таскать весь шкаф на каждую встречу: меньше мусора в памяти — и Claude отвечает точнее.

Анатомия SKILL.md #

В папке Skill лежит главный файл <code>SKILL.md</code> из двух частей:

---
name: мой-тон-км
description: Применять, когда Claude пишет любой текст для людей: заголовки, посты, кейсы, письма клиентам.
---

- Тёплый, живой, без канцелярита и «мы команда профессионалов».
- Короткие предложения. Конкретика вместо прилагательных: «3 поста в неделю», а не «регулярно».
- Обращение на «вы», но без официоза.

# Стоп-слова
- «данный», «является», «эксклюзивный», «индивидуальный подход», «лидер рынка»
  1. Шапка (frontmatter) между <code>---</code>: <code>name</code> — имя (короткое, без пробелов/символов); <code>description</code> — самое важное поле: по нему Claude решает, когда доставать Skill. Плохое описание («всякое про тексты») = Skill молчит или лезет не вовремя. Хорошее отвечает на вопрос «в каких ситуациях применять» словами «применять, когда…».
  2. Тело — правила, шаги, шаблоны. Пишется как инструкция для толкового стажёра.

Первый рабочий Skill: мой-тон-км #

Попробуйте сейчас: создайте Skill «мой-тон-км» по образцу. Потом спросите Claude: «напиши два заголовка для моей услуги — «аудит контента»». Без упоминания Skill. Проверьте: применил ли стиль? Если да — готово.

Post-text-review hook — проверить текст по стилю #

Урок 03.2 — Hooks: Claude сам проверяет стиль #

⏱ ~5 минут · 🎯 Цель: вы настроили hook — Claude после каждой «написал текст»-сессии сам проверил его по стилю-гайду, и никто не должен напоминать.

Что такое hooks #

Hooks — это «рефлексы» Claude: определённые действия, которые Claude делает вместо вас, без специального запроса. Курс предлагает три основных типа:

  • pre-tool-use — перед выполнением инструмента (например, перед записью файла)
  • post-tool-use — после (например, после написания поста — проверить его по стилю)
  • stop — когда Claude хочет закончить — спросить, всё ли правильно

Для КМ самый полезный — post-text-review: после того, как Claude написал текст (пост, кейс, email), проверить его по вашему стилю-гайду.

Как настроить hook на стиль #

Создайте файл <code>.claude/hooks/post-text-review.md</code> (или в папке hooks/ в вашем проекте):


## Когда срабатывает
После того, как Claude написал текст (пост, кейс, email, заголовок) для клиента или витрины.

## Что делать Claude
1. Прочитать файл с текстом
2. Сверить с CLAUDE.md (стиль-гайд) и Skill «мой-тон-км»:
   - Нет ли стоп-слов?
   - Сохранён ли тон (тёплый, живой, без канцелярита)?
   - Короткие предложения? Конкретика?
3. Если есть отклонения — написать их список в виде «исправления», без переписывания (это ваша работа — вы решаете, исправлять или нет)
4. Записать исправления в тот же файл с пометкой «# Ревью Claude [дата]»

Как подключить #

Способ зависит от того, как работаете с Claude Code. Обычно — Claude читает hook из папки hooks/ в проекте и применяет его при соответствующих действиях. Инструкция по подключению — в документации Claude Code (файл hooks/README.md в вашем проекте).

Попробуйте сейчас: создайте файл hook по образцу выше. Создайте тестовый текст (например, черновик поста в <code>планы/тестовый-пост.md</code>), попросите Claude написать его, и посмотрите — сработал ли hook (Claude сам отозвался с ревью?).

Чего hooks НЕ делают #

  • Не переписывают текст за вас. Они показывают, что отклонение, но исправлять — вам (или вам решать, исправить Claude).
  • Не заменяют критика. Hook — это быстрый чек; deep critique (критический разбор структуры, ценности) — это отдельный навык (М07 имеет critic loop).

03-3-mcp-сервисы-claude-заходит-в-ваши-инструменты #

Урок 03.3 — MCP-сервисы: Claude заходит в ваши инструменты #

⏱ ~10 минут · 🎯 Цель: вы поняли, что MCP (Model Context Protocol) — это «руки» Claude к внешним сервисам — и подключили первый MCP: календарь илиSimplenote для контент-планов.

Для чего MCP контент-менеджеру #

MCP — это способ дать Claude возможность работать с вашими сервисами: читать календарь, отправлять Slack-сообщения, писать в Notion, забирать аналитику из соцсетей. Без MCP Claude — только текст. С MCP — Claude делает вещи в вашем инструментарии.

Для контент-менеджера три самых полезных MCP:

СервисЧто Claude делает с нимЗачем
Google Calendar / OutlookЧитать ваш календарь, видеть свободные слотыПланировать публикации, встречи с клиентами без ручного ввода
Notion / Google DocsПисать и читать тексты в ваших рабочих документахПрямой поток в ваши инструменты, не дублировать
Telegram Bot API / RSSПолучать новые посты, анализировать трендыАвтоматический мониторинг конкурентов и тематик

Курс не устанавливает все MCP сразу — мы начинаем с одного, чтобы вы поняли механику. Простой MCP — это сервис, который даёт Claude читать хотя бы один файл или получать одну информацию.

Пример: MCP для календаря #

Предположим, вы работаете с Google Calendar (или аналогом). MCP-сервер календаря даёт Claude возможность:

  • Посмотреть, какие дни у вас заняты
  • Найти свободный слот для публикации контента
  • Добавить напоминание «опубликовать пост сегодня» (по вашей команде)

Для этого Claude «дёргает» MCP-сервер, который идёт в календарь, читает, и обратно. Claude сам с вашего календаря не уходит — MCP-сервер это делает.

Как начать #

  1. Выберите один сервис, который используете чаще всего (календарь, Notion, Telegram).
  2. Найдите MCP-сервер для него (в документации Claude Code, в интернете «MCP сервер для X»). Часто это уже написанный сервер, который нужно только подключить.
  3. Подключите к Claude Code (конфигурация в <code>.claude/mcp.json</code> или через интерфейс Claude Code).
  4. Проверьте: спросите Claude «сегодня в календаре какие свободные слоты?» — если ответил — MCP работает.

Попробуйте сейчас: подключите один MCP (любой, который у вас есть). Потом спросите Claude за информацию из этого сервиса (например, «в календаре какие события на завтра?»). Если ответил — MCP работает.

Чего не делать с MCP #

  • Не давать Claude доступ к тем сервисам, где стоят личные данные или секреты (это М07-безопасность). Календарь — в целом безопасно (ваши события, не чужие).
  • Не перегружать сразу всеми сервисами — один для начала.

03-4-critic-loop-claude-критикует-текст-а-не-только-пишет #

Урок 03.4 — Critic loop: Claude критикует текст, а не только пишет #

⏱ ~6 минут · 🎯 Цель: вы научились запускать critic loop — Claude оценивает текст по критериям, которые вы задаёте, и говорит, что можно улучшить.

Зачем критиковать, если Claude уже пишет #

Когда Claude пишет текст «по заданию» — он исполняет. Но исполнение ≠ качество. Critic loop — это отдельный запуск Claude в роли критика, который смотрит на текст со стороны и оценивает по вашим критериям:

  • Ясность заголовка
  • Ценность для посетителя
  • Тон (соответствие стилю)
  • Конкретика (цифры, примеры, не общие слова)
  • Призыв к действию (есть ли, понятен ли)

Как запускать critic loop #

Самый простой способ — отдельный навык «критик»:

  1. В папке <code>.claude/skills/</code> создайте <code>критик.md</code> с описанием:
    ---
name: критик
description: Применять, когда Claude пишет текст, который нужно проверить. Проверить по критериям, которые даёт пользователь.
---

# Критик

Вы — критик текста. Ваша задача — не хвалить и не портить, а честно оценить по критериям.

Критерии оценки задаёт пользователь (задаёте в запросе).

Формат ответа:
- ✅ Хорошо: [что получилось]
- ⚠️ Можно улучшить: [что и как]
- ❓ Вопрос: [что непонятно в тексте]
  2. Запускайте критик как отдельный навык: «примени навык критик к этому посту [вставить] — критерии: [ваши критерии]».

Deep критика (в режиме Cowork)Разбор структуры, ценности, аудитории — Claude задаёт вопросы вам, а не просто отчётКогда текст — важный (лендинг, первый кейс, важный email)

Урок 03.5 — Диспетчер Claude: работает на расписание #

⏱ ~4 минуты · 🎯 Цель: вы поняли, что Claude может работать не только «когда вы его вызываете» — но и по расписанию (например, течение контент-плана без вашего участия).

Расписание Claude (Routine / Dispatch) #

Claude Code поддерживает запуск определённых задач по расписанию — это значит, что Claude «прокидывается» в определённое время и делает то, что вы настроили. Для контент-менеджера самый очевидный пример:

  • Утром (9:00) — Claude читает календарь (через MCP), смотрит, какие публикации должны быть сегодня, напоминает вам (или сам публикует, если настроено).
  • Вечером (18:00) — Claude собирает аналитику за день (если настроены метрики) и пишет отчёт в ваш Notion/Docs.

Это не «пусть Claude работает вместо меня» — это «Claude напоминает и собирает данные, я решаю, что с ними делать».

Первый диспетчер: напоминание о публикации #

Настройте простой рутин:


## Время срабатывания
Каждый день в 9:00 (или ваше рабочее утро)

## Что делать Claude
1. Открыть файл `планы/календарь-публикаций.md` (или ваш календарь через MCP)
2. Найти публикации, запланированные на сегодня
3. Написать вам сообщение (в чат Claude, в Slack, в Telegram — настроенное) слайтом: «Сегодня запланировано: [список]»
4. Если ничего — ничего не отправлять

Чем это полезно #

Это рабочий стол текущей сессии (уроки М01 и М03): всё, что лежит в открытом разговоре. Живёт до <code>/clear</code>, портится от длины (context rot), лечится <code>/compact</code>. Уровень 3. Long-term — «навсегда» #

Знания, которые вы хотите иметь доступными между проектами, между годами: бренд-ассеты (логотипы, цветовые схемы, шрифты), глоссарий (какие термины вы используете), кейсы, которые вы положили в портфолио, стиль-гайды от разных проектов.

Память Long-term — «что я знаю о конtent-менеджменте вообще, и знаю всегда».

Урок 04.2 — Project-память: CLAUDE.md, Skills, бриф — всё в папке #

⏱ ~6 минут · 🎯 Цель: вы убедились, что всё, что Claude должен знать о вашем проекте «Валентина», живёт в папке проекта и не потеряется при смене сессии.

Уровень Project-памяти — это не «одна база» — это структура папки #

С вами уже есть папка проекта (М01, М02):

контент-менеджер/
├── CLAUDE.md          ← проектные правила (стиль, запрещённые слова, структура)

  • Стиль-гайд — обновляется, когда вы осознаёте, что какое-то правило не работает.
  • Глоссарий — пополняется, когда в работе появляется новый термин, который важно понимать одинаково.

04-3-long-term-память-obsidian-или-аналог-ваш-второй-мозг #

Урок 04.3 — Long-term память: Obsidian (или аналог) — ваш второй мозг #

⏱ ~10 минут · 🎯 Цель: вы создали Long-term память в виде Obsidian vault (или аналога) — и положили туда первое знание, которое должно «пережить» все проекты.

Для чего Long-term память контент-менеджеру #

Claude знает проект, но не «всё, что вы когда-либо знали о контент-менеджменте». Если вы работали с 10 клиентами, у каждого свои кейсы, свои стилевые особенности, свои уроки — Claude этого не знает, если это не в Project-памяти этого проекта.

Long-term память — это ваш второй мозг: совокупность знаний, которые вы накапливаете, и которые Claude может запускать по запросу.

Как это устроено (на примере Obsidian) #

Obsidian — это программа для заметок, где всё хранится как Markdown-файлы в папке (vault). Преимущества для КМ:

  • Локальные файлы — ваши данные у вас, не в облаке (если не хотите).
  • Markdown — те же файлы, что и в Claude-проекте — совместимость.
  • Поиск + связи — можно связать «кейс магазин-клиент» с «урок: почему клиенты уходят».
  • Claude может читать Obsidian vault — если дать ему доступ (через папку или Obsidian API/MCP).

Первые файлы в Long-term памяти #

Создайте vault (папку) <code>second-brain/</code> и положите туда первые файлы:

second-brain/
├── index.md              ← «что здесь лежит» — карта знаний
├── бренд-ассеты/         ← логотипы, цветовые схемы, шрифты (файлы + описания)
├── глоссарий-общий.md    ← термины, которые используете во всех проектах
├── кейсы-архив/         ← кейсы из завершённых проектов (обезличенные)
├── стили-клиентов/       ← стилевые предпочтения клиентов (если важно)
└── уроки-работы/         ← «что я понял, работая с этим клиентом / этой нишей»

Как Claude получает доступ к Long-term памяти #

Есть два пути:

  1. Папка на том же компьютере — Claude Code видит файлы в <code>second-brain/</code> (если это ваша машина). Спрашиваете Claude: «в моём втором мозге, в папке бренд-ассеты, поищи, что мы используем для цветов» — Claude ищет.
  2. Obsidian MCP — если Obsidian запущен и настроен MCP-сервер, Claude может читать vault через него (то же, что и календарь в М03).

Попробуйте сейчас: создайте папку <code>second-brain/</code> (или Obsidian vault). Положите туда файл <code>глоссарий-общий.md</code> с тремя терминами, которые используете во всех проектах. Потом спросите Claude: «в моём втором мозге — что мы называем [термин]?» и проверьте, находит ли.

04-4-notebooklm-или-альтернатива-когда-документов-очень-много #

Урок 04.4 — NotebookLM (или альтернатива): когда документов очень много #

⏱ ~5 минут · 🎯 Цель: вы поняли, зачем NotebookLM (или аналог) нужен, когда у вас много документов, и как Claude «понимает» их.

Когда три уровня недостаточно #

Project-память и Long-term (Obsidian) — это «файлы, которые Claude читает». Но если у вас:

  • 50+ кейсов в течение года
  • 200+ страниц бренд-гайдов клиентов
  • 10+ видео-интервью с клиентами

— читать их все вручную долго, а Claude не может «прочитать всё» за раз (контекст ограничен). Здесь появляется инструмент вроде NotebookLM (Google) — «библиотека документов, которые Claude (или другой AI) может «понимать» через эмбеддинги и векторный поиск».

Что такое NotebookLM (просто) #

NotebookLM — это «библиотека», куда вы загружаете документы (PDF, Google Docs, текстовые файлы, скриншоты), и AI может «понимать» их содержимое, отвечать на вопросы по ним. Вы не скармливаете Claude 50 страниц — вы скармливаете NotebookLM, а Claude спрашивает у неё: «что в кейсе про магазин-клиент написано про конверсию?».

Для чего КМ #

  • Глубокий анализ кейсов. Если у вас много кейсов, NotebookLM позволяет искать «какие кейсы показали рост конверсии после контента» — не читая все вручную.
  • Анализ бренд-гайдов клиентов. Если у вас длинные PDF-брендбуки клиентов, NotebookLM может отвечать на вопросы по ним.
  • Саммари длинных документов. «Сделай краткое содержание этого бренд-гайда — 5 пунктов» — NotebookLM это умеет.

Как начать #

  1. Создайте NotebookLM (в Google — бесплатно, notebooklm.google).
  2. Загрузите туда 3–5 ваших кейсов (файлы из <code>second-brain/кейсы-архив/</code>).
  3. Спрашивайте NotebookLM: «какие кейсы показывают рост после контента-стратегии?».

Попробуйте сейчас: создайте NotebookLM (или аналог, если предпочитаете другой сервис). Загрузите 2–3 файла кейсов. Спросите: «что общего у этих кейсов в решении проблем клиентов?». Получите обобщение.

05-1-что-такое-hermes-оператор-и-зачем-он-км #

Урок 05.1 — Что такое Hermes-оператор и зачем он КМ #

⏱ ~5 минут · 🎯 Цель: вы поняли, что Hermes — это не «ещё один AI» — это Claude в форме оператора с постоянной ролью и набором рутин, который работает на вас, когда вы заняты.

Hermes — в мифологии вестник и помощник, которому все двери открыты #

Курс зовёт Hermes-оператором — личного ИИ-оператора: специально оформленную «смену» Claude, у которой:

  1. Постоянная роль — «я ваш ИИ-оператор по контенту», а не «я AI-ассистент на все темы».
  2. Подключения ко всем инструментам — календарь, Notion, Obsidian, Telegram, email, всё, к чему у вас есть доступ.
  3. Набор рутин — что делать в какое время, что напоминать, что собирать.

Зачем оператор контент-менеджеру #

Без оператора вы — единственный, кто всё помнит. С оператором:

  • Утром — Claude (Hermes) напоминает: «сегодня запланировано публикаций: 2 поста, 1 email. Аналитика вчерашних — готова, вот цифры».
  • Перед встречей с клиентом — Claude собирает краткую справку: «клиент X, сфера Y, последний кейс Z, незакрытые вопросы».
  • Вечером — Claude собирает отчёт: «сегодня опубликовано 2 поста, новые подписчики X, клики Y».

Это не замена вашей работе — это освобождение ваших сил для стратегии и творчества.

Разница между «задать вопрос» и «иметь оператора» #

  • Спросить Claude: «напиши пост» — Claude пишет, вы используете. Конец.
  • Иметь оператора: Claude знает, что сегодня 12 марта, что вы планировали пост на 14:00, что стиль — мой-тон-км, что кейс-шаблон — в папке кейсы — и сам предлагает: «готов черновик поста, потверждаете?».

Оператор — это не «быстрее пишет» — это «знает контекст, напоминает, собирает».

Что оператор подкачивает #

Оператор — не «делает всё сам». Он подкачивает данные, которыми вы потом пользуетесь.

Для КМ — три основных источника данных для оператора:

ИсточникЧто оператор подкачиваетЗачем
Календарь / планыЗапланированные публикации, встречиНапоминания, управление расписанием

Как подкачать кейсы #

Оператор может помочь вам «подкачать» кейсы из Obsidian в лендинг (М02).

Пример:

Hermes: ищет в Obsidian (second-brain/кейсы-архив/) кейсы, которые подходят под описание. Находит 3.
Отдаёт вам краткие анногации: «вот 3 кейса, которые можно использовать».

Это экономит время: вам не нужно искать кейсы вручную — оператор находит.

Правила безопасности для Hermes-оператора #

Из курса М07-безопасность (Модуль 09 оригинала, адаптирован под КМ):

  1. Не отдавать персональные данные клиентов. Claude (оператор) не знает ФИО клиентов, телефоны, адреса — только обезличенные данные. Если в Obsidian есть кейсы с «клиент из Омска, стоматология» — это ок. Если «клиент Иван Иванов, +7...» — обезличить.
  2. Не отправлять от вашего имени. Оператор может напомнить «нужно отправить email клиенту» — но отправляет email вы (или настроенная автопубликация).
  3. Не менять планы без одобрения. Если оператор видит, что план не сбывается (например, клиент не ответил на email) — он напоминает, но не передаётся клеFIGа.
  4. Секреты — в Bitwarden (или аналог), не в чате. API-ключи, пароли от сервисов — не в обычном чате с Claude, в сейфе.

Урок 06.1 — Первые принципы: разбираем любой проект КМ по косточкам #

⏱ ~8 минут · 🎯 Цель: у вас есть шаблон разбора любого проекта контент-менеджера по четырём шагам — и вы прогнали через него свою реальную идею.

Первые принципы — не «как другие делают», а «что здесь необходимо» #

First principles (первые принципы) — способ думать, которым курс предлагает разбирать любую систему: не «как делают другие» (это копирование), а «что здесь правда и что физически необходимо».

Аналогия: шеф, который готовит «как в том ресторане», повторяет чужие ошибки; шеф, который спросил «что делает блюдо вкусным: баланс соли, кислоты, текстуры?», собирает своё.

Для контент-менеджера — четыре шага разбора #

  1. Зачем на самом деле? Одна строка результата, ради которого всё затевается. Не «сделать контент», а «клиент доплачивает остаток без звонков» или «бизнес получает +5% конверсии после контент-стратегии».
  2. Разобрать до деталей. Что необходимо, чтобы результат случился? Список атомов: данные (аналитика, исследования), действия (статьи, посты, email), уведомления (напоминания, публикации), деньги (оплата клиента).
  3. Вычеркнуть лишнее. Убрать всё, без чего атомы работают. Половина «фич» умирает на этом шаге со словами «а это зачем?».
  4. Собрать заново простейшим способом. Готовые сервисы вместо своих (Notion вместо самописной базы, Vercel вместо сервера), Claude вместо ручного труда — где возможно.

Break any problem down: шаблон (заберите себе) #


1. Результат одной строкой: [клиент доплачивает остаток без звонков]
2. Атомы (что необходимо):
   - [данные: аналитика причин оттока]
   - [действия: email-цепочка для новичков]
   - [действия: обновление контента магазина]
   - [уведомления: напоминание о публикации]
   - [деньги: предоплата 50%]
3. Вычеркнуть лишнее:
   - [скорость загрузки сайта — не в этой задаче]
   - [видео-контент — не нужно для первой версии]
4. Собрать простейшим способом:
   - Claude для написания email-цепочки
   - Vercel для лендинга аудита
   - Notion для трекинга

BLAST — модель сдачи работы #

BLAST — это схема, по которой курс передаёт работу клиенту. Аббревиатура (как курс расшифровывает):

  • Brief — бриф (М02)
  • Livestream / Lessons — обучение/витрина (М05-06)
  • Assets — ассеты (М04)
  • Stack — стек инструментов (М02-03)
  • Triage / Testing — тестирование, приёмка (этот урок)

Модель BLAST для КМ — это не «отдать файлы» — это «передать систему, которая работает».

Приёмка — по брифу, а не по настроению #

Последний stage — приёмка. В курсе — ритуал приёмки: вы и клиент открываете BRIEF.md и проверяете, что каждая строка брифа выполнена. Не «мне нравится / не нравится» — «заявлено в брифе X, есть ли это в работе?».

Это снижает конфликты: не «вы неправильно поняли», а «заявлено X, сделано X / не сделано — давайте исправим».

Почему пакеты — лучший способ продавать контент-менеджмент #

Курс рекомендует продукт вместо услуги: пакеты с именем, границами и сроком — клиент покупает как товар, вы считаете как конвейер.

Почему часы — плохо:

  • «20 часов работы» клиенту неинтересно. «Сайт, который приводит заявки» — интересно.
  • Часы продают исполнителя в очередь; результат продаёт партнёра в сделку.
  • По часам — вы делим ценность с клиентом по времени, а не по результату.

Ценообразование — пол, потолок, смелость #

  1. Себестоимость × коэффициент — пол для новичка; продаёт время.

Урок 06.4 — Лидогенерация без холодных рассылок: от аудита к сделке #

⏱ ~8 минут · 🎯 Цель: у вас есть механизм получения клиентов без холодных рассылок — через публичную стройку и магнит-аудит.

Почему холодные рассылки — не лучший путь для КМ #

Курс не против рассылок (М03-диспетчер их использует), но для КМ существуют более эффективные способы:

  1. Публичная стройка: раз в неделю вы строите что-то в открытую (запись, разбор) — это контент, который приводит людей, которые уже видели вас за работой.
  2. Магнит-аудит: бесплатный одностраничный аудит (например, «3 вещи, которые можно улучшить на вашем сайте / в контенте») — приводит заявку; заявка, пришедшая сама, конвертируется в разы холодного списка.
  3. Ниша «отрасль × боль»: «контент-оптимизация для магазинов, которые теряют клиентов после покупки» бьёт сильнее, чем «контент-менеджер».

Как устроен магнит-аудит #

Магнит-аудит — это бесплатная одностраничка (PDF или лендинг), которую вы отдаёте клиенту в обмен на контакт / встречу.

Содержание магнита-аудита (пример):

  1. Что проверяете — 3–5 пунктов (что вы смотреть будете)
  2. Критерии — по каждому пункту: как оцениваете
  3. Пример — один обезличенный пример («клиент X, сфера Y, проблема Z — решение W»)
  4. Результат — что клиент получит после аудита (не более 3 строк)
  5. Призыв — «записать на 20-минутную встречу, где разберём ваш контент»

Магнит работает как «образец вашей работы» — клиент видит, что вы умеете анализировать, и это даёт доверие для большей сделки.

Попробуйте сейчас: напишите черновик магнита-аудита для вашей ниши (например, «Контент-аудит для магазинов опта»). 1 страница, 3 критерия, 1 пример, призыв. Положите в папку <code>витрина/магнит-audit.md</code> — как черновик.

Деньги лежат в дожиме #

Урок 07.1 — Claude Code Design: дизайнер, который сразу пишет код #

⏱ ~8 минут · 🎯 Цель: вы попробовали дизайн-режим Claude на вашем лендинге и поняли, когда он заменяет Figma, а когда — нет.

Claude Code Design — что это #

Claude Code Design — свежая дизайн-способность Claude: вы говорите «сделай три варианта блока цен», а он показывает визуальные варианты и тут же превращает выбранный в код. Без «дизайнер нарисовал → разработчик понял по-своему»: один исполнитель ведёт от эскиза до живого блока.

Для КМ без дизайнера — это главное: спорить о пикселях не нужно — вы тычете в вариант и говорите «вот этот, но воздух как во втором».

Когдa использовать Claude Code Design, а когда — Figma/Stitch #

Три инструмента, три роли:

ИнструментРольКогда для КМ
FigmaПиксельная точность с передачей макетаКогда в команде есть дизайнер; вам — не сейчас
Stitch (Google)Быстро накидать UI-макеты «на посмотреть»Хорош для разведки идей (например, «как будет выглядеть секция кейсов?»)
Claude Code DesignКаогда макет должен сразу стать живым сайтом и у вас нет дизайнераКогда лендинг нужно сделать самому — это ваш выбор

Правило курса:

  • Нет дизайнера и цель — живой сайт → Claude Code Design
  • Нужна стена идей на час → Stitch
  • В команде дизайнер с пиксель-перфектом → Figma, а Claude пишет код по макету

Живой пример: блок кейсов на лендинге #

Вы просите Claude: «три варианта секции кейсов для лендинга контент-менеджера, стиль — мой-тон-км, по брифу из BRIEF.md». Claude показывает три варианта. Вы выбираете один и говорите: «делай». Claude превращает его в код в <code>витрина/</code>.

Это экономит дни работы: не «попросить дизайнера, получить макет, передать разработчику, получить код» — всё в одном месте.

Попробуйте сейчас: открыть Claude Code Design (если доступно — уточните в Claude Code) и сделать запрос: «три варианта секции услуг для лендинга КМ, стиль — мой-тон-км». Выбрать один вариант и попросить реализовать.

Урок 07.2 — Презентация для клиента: как показать результат до начала работы #

⏱ ~8 минут · 🎯 Цель: у вас есть шаблон презентации для клиента — «показать, что вы сделаете, до того, как начали».

Зачем презентация клиенту #

Тот, кто нанимает контент-менеджера, часто не понимает, что именно он получит. Презентация (дековский документ, 5–7 слайдов) показывает:

  • Ваш подход — как вы думаете, планируете, работаете
  • Примеры работ — кейсы из М04
  • Результат для клиента — не «я напишу посты», а «клиент получит X»

Это заменяет «обещания» на «показать».

Структура презентации (5–7 слайдов) #

  1. Проблема клиента — «что не так с вашим контентом сейчас» (по вашему анализу)
  2. Куда двигаем — «какой результат возможен» (с цифрой/примером из кейсов)
  3. Как работаем — ваш процесс (BLAST из М06, конвейер, Claude-оператор)
  4. Пакет — что входит, сроки, цена (из М06)
  5. Кейсы — 1–2 примера (обезличенные, из М04)
  6. Вопросы для вас — вы спрашиваете клиента (а не просто презентуете)

Это презентация «системы», а не «продажи» — вы показываете, что вы professionals, а не «пишу посты за деньги».

Что нельзя отдавать Claude #

Правило нуля курса (из оригинального М09-безопасность, адаптирован под КМ):

В любой AI-инструмент не уходит то, что вы не готовы увидеть на первой странице новостей. Конкретно:

  • Коммерческую тайну (договоры клиентов «целиком», секретные стратегии) — если нельзя показывать.
  • Где вы работаете с медицинскими, финансовыми данными — удваивайте осторожность (даже если юридически не обязаны).

Как обезличивать кейсы и работы #

Из М04 (Long-term память) и М06 (кейсы):

  • «Клиент из Омска, мебельный магазин» вместо имени и фамилии.

Урок 07.4 — Ценообразование по ценности: как сделать первый чек #

⏱ ~8 минут · 🎯 Цель: вы пересчитали пакет «Рост» по ценности на реальном кейсе и настроили Stripe для счёта.

Цена по ценности — не «сколько стоит мой час», а «сколько стоит результат клиенту» #

Из М06-цены (Модуль 10 оригинала):

Три способа цены, от слабого к сильному:

  1. Себестоимость × коэффициент — пол для новичка; продаёт время, ловит в ловушку «дорого за часы».
  2. Рынок — «так стоит у других»: безопасно, но чуть дёшево, потому что сравнивают универсалов.
  3. Ценность — доля от созданной ценности.

Пример: пересчёт пакета «Рост» по ценности #

Предположим, ваш пакет «Рост» (М06) — 3 месяца контента + система + отчётность — и вы оцениваете его как 180 000 руб. Это много? Мало? Зависит отц ОЦЕНКЕЦЕННОСТИ.

Пример:

  • Клиент — магазин мебели. Проблема: теряет 30% клиентов после первой покупки.
  • Если контент-стратегия спасает 10% клиентов — это 10% от 30% = 3% от общих продаж.
  • Если оборот магазина 5 млн руб./мес — 3% = 150 000 руб./мес.
  • За 3 месяца = 450 000 руб. прибыли клиента.
  • Пакет 180 000 руб. = 40% от созданной ценности. Доступно.
  • Если клиент не верит — снизить до 120 000 (потолок = ценность, пол = рынок: сколько стоят другие).

Как сделать счёт (Stripe или аналог) #

Фреймворк курса (М06-внедрение):

  • Stripe Invoicing (или аналог в РФ — ЮKassa, CloudPayments) — счёт с предоплатой.
  • 50% предоплата открывает слот — это не недоверие, а фильтр серьёзности и ваше спокойствие.
  • 50% — по приёмке — когда BLAST последний stage (приёмка по брифу) пройден.

Попробуйте сейчас: пересчитайте пакет «Рост» по ценности на гипотетическом клиенте (или реальном, если есть). Если цена упирается в «рынок» — запишите, какой результат клиента вам нужен, чтобы цена оправдалась.

Пост для соцсети — стиль контент-менеджера #

name: пост-для-соцсети description: Применять, когда Claude пишет пост для Instagram, Telegram или LinkedIn от имени контент-менеджера.

Основы #

  • Один пост — одна мысль. Не распирать пять проблем в одном посте.
  • Конкретика вместо общих слов. «3 поста в неделю» — не «регулярно». «+18 подписчиков за день» — не «много».
  • Короткие предложения. Больше 20 слов — разбивать.
  • Эмодзи допустимы, но не декорация, а акцент (— один на пост, максимум два).
  • Обращение на «вы», без официоза.

Структура поста #

  1. Первая строка — зацепка. Либо вопрос клиента, либо цифра, либо ситуация. Не «сегодня поговорим о…».
  2. Основной блок — один аргумент / один шаг / один пример.
  3. Итог в 1–2 строках — вывод, приглашение к действию, вопрос.
  4. Призыв (опционально) — если пост не риторический.

Пример (заполненный) #

Первая строка: «Клиент купил товар, а через неделю — ушёл. Вы знаете, где болит?»

Основной: «Уходит не от цены — от непонимания, зачем второй раз тратить. Когда контента после покупки нет — клиент «вылетает». Два шага, которые это исправляют: (1) email-цепочка на 5 дней с полезным, не продающим, (2) 2 поста в соцсетях на тему «что делать после покупки». Небольшой контент — большая удержка.»

Итог: «Контент после продажи — не «добавить», а «удержать».»

Слайд 1 — Проблема клиента #

Заголовок: «Сейчас с вашим контентом происходит…»

Как заполнить:

  • Одна-две строки, конкретная проблема (а не «контент слабый»).
  • Опирайтесь на анализ (магнит-аудит, М06, урок 06.4) или результаты общения с клиентом.
  • Не обвинять — описывать ситуацию.

Пример:

«Магазин запустил сайт, но клиенты приходят, смотрят и уходят — 30% оттока после первой покупки. Контента после продажи нет — клиент «вылетает».»

Слайд 2 — Куда двигаем #

Заголовок: «Результат, который возможно»

Как заполнить:

  • Одна строка с цифрой или конкретным результатом.
  • Если цифры пока нет — «пример из кейса» (обезличенный, М04).
  • Не обещайте — покажите возможное направление.

Пример:

«При контент-стратегии — возможность снизить отток на 10% в первый квартал. По аналогии с кейсом «трансформация контента магазина» (М04) — 3 недели контента + email-цепочка = клиенты возвращаются.»

Слайд 3 — Как работаем #

Заголовок: «Мой процесс»

Как заполнить:

  • 3–5 шагов вашего процесса (BLAST из М06, конвейер, Claude-оператор из М05).
  • Не «я пишу посты» — «я решаю проблему контента так-то».
  • Упомянуть инструменты, если это часть ценности (Claude, Vercel, Obsidian).

Пример:

  1. Аудит — разбираю, почему уходят клиенты (интервью, аналитика, конкурентный обзор)
  2. Стратегия — формулирую, какой контент нужен, где и зачем
  3. Реализация — пишу контент (с Claude-оператором), настраиваю публикации, дежурит по расписанию
  4. Отчётность — каждую неделю: что опубликовано, цифры, уроки

  • Цена (если уже определили, или «согласую после аудита»).

Пример (Система):

Пакет «Система» — 1 месяц

Входит:

  • Аудит текущего контента (1 раз)
  • Контент-стратегия (карта публикаций на месяц)
